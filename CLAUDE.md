# CLAUDE.md — приложение «Kim?» (рабочее название)

> «Кім?» по-казахски — «Кто?». Название временное, поменять легко.
> Этот файл — постоянный контекст проекта. Читай его перед каждой задачей.

## 1. Что за продукт

Мобильная социальная игра для близких друзей (iOS + Android).

**Основной цикл:**
1. Пользователь создаёт или вступает в «круг» (5–30 человек: друзья, класс, группа, коллеги) по ссылке-приглашению.
2. Раз в день, в случайное время с 10:00 до 21:00 по времени круга, всем участникам приходит push: «Вопрос дня!».
3. Вопрос формата «Кто из нас…?» — участник голосует за одного друга из круга (не за себя).
4. После голосования видит результаты. Голоса анонимны: человек видит, сколько раз его выбрали, но не кем.
5. В воскресенье — «Итоги недели»: карточка-картинка для сторис Instagram/TikTok.
6. Участники могут предлагать свои вопросы (с модерацией, см. раздел 5).

**Аудитория:** 14–25 лет, Казахстан (старт — Атырау), дальше СНГ.
**Языки интерфейса:** русский (ru) и казахский (kk). Все строки — только через i18n, никакого хардкода текста в компонентах.

## 2. Главные принципы (нарушать нельзя)

1. **Только позитив.** Никаких вопросов про внешность, вес, ум в негативном ключе, «кто хуже всех».
2. **Голоса анонимны.** Поле `voter_id` никогда не уходит на клиент другим пользователям. Результаты — только агрегаты через RPC/view.
3. **Нет свободного текста между пользователями.** Нет чата, нет анонимных сообщений, нет комментариев. Единственный пользовательский текст — предложенные вопросы, и они проходят модерацию.
4. **Вся проверка безопасности — на сервере** (RLS, Edge Functions). Клиентские проверки — только для удобства UX, на них не полагаемся.
5. **Простота.** Не добавляй фичи, библиотеки и экраны, которых нет в текущей задаче. Если считаешь, что что-то нужно, — спроси.

- **Состояние/данные:** @tanstack/react-query для серверных данных, zustand для локального состояния (если реально нужно).
- **Сборка:** EAS Build (облако, Mac не требуется), EAS Submit.
- **Подписки:** RevenueCat (позже, шаг 11).

## 4. Модель данных (Supabase)

Все таблицы — с RLS **включённым**. Все изменения схемы — только через миграции в `supabase/migrations/`.

```
profiles          id (= auth.users.id), username (unique), display_name, avatar_url,
                  locale ('ru'|'kk'), can_submit_questions (bool, default true),
                  is_banned (bool), created_at
circles           id, name, invite_code (unique, короткий), owner_id, timezone (default 'Asia/Almaty'),
                  created_at
circle_members    circle_id, user_id, role ('owner'|'admin'|'member'), joined_at
                  PK (circle_id, user_id)
questions         id, text_ru, text_kk, pack ('friends'|'toi'|'school'|'work'|'future'|'warm'),
                  source ('system'|'user'), author_id (null для system), circle_id (null = глобальный),
                  status ('pending'|'approved'|'rejected'|'hidden'), report_count, created_at
question_approvals question_id, user_id, created_at  PK (question_id, user_id)
daily_rounds      id, circle_id, question_id, round_date, starts_at, ends_at
                  UNIQUE (circle_id, round_date)
votes             id, round_id, voter_id, target_id, created_at
                  UNIQUE (round_id, voter_id), CHECK (voter_id <> target_id)
reports           id, reporter_id, question_id (null), reported_user_id (null), reason, status, created_at
blocks            blocker_id, blocked_id  PK (blocker_id, blocked_id)
push_tokens       user_id, token, platform, updated_at
```

**Правила RLS (кратко):**
- Пользователь видит круги, участником которых является, и их участников.
- `votes`: пользователь может вставить только свой голос (`voter_id = auth.uid()`), только в активный раунд своего круга, только за участника этого круга. **Читать `votes` напрямую не может никто из клиентов** — результаты только через RPC `get_round_results(round_id)`, возвращающую `target_id + count`.
- `questions`: глобальные `approved` видят все; вопросы круга — только его участники.
- `reports`, `blocks` — пользователь видит только свои.

## 5. Пользовательские вопросы и модерация

- Вопрос всегда строится по шаблону: префикс «Кто из нас…» / «Біздің арамызда кім…» + окончание от пользователя.
- Окончание: 10–100 символов, без ссылок, без эмодзи-спама.
- Отправка — только через Edge Function `submit-question`, которая:
  1. проверяет, что пользователь в круге, не забанен и `can_submit_questions = true`;
  2. лимит: максимум 3 предложения в сутки на пользователя;
  3. прогоняет текст через стоп-лист (ru + kk, файл `supabase/functions/_shared/stoplist.ts`) — мат, оскорбления, внешность, вес;
  4. отклоняет текст, если в нём есть имя, ник или display_name любого участника круга;
  5. сохраняет со статусом `pending`.
- Вопрос становится `approved` (и входит в ротацию этого круга), когда его одобрили **2 других участника** или **админ/владелец круга**.
- Жалоба на вопрос → статус сразу `hidden`, вопрос пропадает из ротации до проверки.
- Если на вопросы автора пришло 3+ подтверждённых жалобы → `can_submit_questions = false`.
- Админ/владелец круга может удалять вопросы и исключать участников.

## 8. Правила работы

- Работай **маленькими шагами**. В конце каждого шага: что сделано, как проверить на телефоне, что осталось.
- Перед большими изменениями — сначала план, потом код.
- Пиши понятные комментарии на русском там, где логика неочевидна.
- Логику (голосование, раунды, модерация, лимиты) покрывай тестами.
- Никаких секретов в коде: ключи — в `.env` (и `.env` в `.gitignore`), секреты Edge Functions — через `supabase secrets`.
- Сервисный ключ Supabase (`service_role`) **никогда** не попадает в мобильное приложение.
- Я не профессиональный программист: объясняй команды, которые мне нужно запустить, простыми словами.
